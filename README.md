# Broadcaster

Listens to `android` notifications and execute a `ReactorAction` or a Callback upon `Posting` of `notification`  
it is primarily from sending notification from `android` to another place via internet  

Which would explain the structure of `ReactorConfig`:
```kotlin
data class ReactorConfig(
    val name: String = "Untitled",
    val method: String = "POST", // "GET" or "POST"
    val endpoint: String = "",
    val bodyLua: String = """
        -- Example lua script
        
        function getOutput()
            return utils:toJson({
                text = string.format("%s@%d: %s", data.name, data.timestamp, data.content)
            })
        end
    """.trimIndent(),
    val ctype: String = "application/json",
    val expected: List<Int> = listOf(200, 204)
)
```

## Body Generation
The body is generated by executing a `lua` script (which is `bodyLua` attr of ReactorConfig)  
The `lua` have exposure to:  
- `data` (`SenderData.kt`):
  - `id`            -> the package name of the posting application
  - `name`          -> the Title of the notification or the Tag of the notification or the id
  - `content`       -> the Text of the notification + if BigText (`=== More Info ===` + BigText) + SubText
  - `timestamp`     -> the EPOC timestamp of the notification (namely the `when` attr)
  - `extras`        -> everything else
- `utils` (`LuaUtils` private object of `DataConversation.kt`):
  - `fromJson`      -> converts the provided str into a lua table (nullable)
  - `toJson`        -> converts table, primitive types into JSON equivalent (optional boolean will pretty print if true)
  - `fromTimestamp` -> converts EPOC timestamp to "dd MMM yyyy, hh:mm a" string (e.g.: `18 AUG 1999, 4:20 PM`)

### USAGE:
Basically, `data` and `utils`, are tables with mentioned function/values as its entries  
use `.` notation to access them (i.e. `data.name`, `utils.toJson`), not `:` (i.e. `data:name`, `data:fromJson`)  
The provided script must have a function named `getOutput` with zero arguments, and it must return a `string` which must match with `ctype` mentioned in `ReactorConfig`.  
```lua
function getOutput()
    return "am i adhering to my ctype?"  -- Nope
end
```

A more complete example suitable for telegram posting would be:
```lua
local function is_empty(str)
    return str == nil or str == "" or (type(str) == "string" and str:match("^%s*$") ~= nil)
end

local function select_from(...)
    for i = 1, select("#", ...) do
        local v = select(i, ...)
        if not is_empty(v) then
            return v
        end
    end
    return nil
end

local function escape_html(str)
    if type(str) ~= "string" then return str end
    return str:gsub("&", "&amp;"):gsub("<", "&lt;"):gsub(">", "&gt;")
end

function getOutput()
    local prefix = "DEVICE_IDENTIFIER"
    local id = select_from(data.id, "??Unknown??")
    local time = select_from(utils.fromTimestamp(data.timestamp), "18 AUG 1999, 4:20 PM")

    local sender = escape_html(select_from(data.name, id))
    local content = escape_html(select_from(data.content, "<Empty Message>"))
    local safe_id = escape_html(id)
    local safe_prefix = escape_html(prefix)
    local safe_time = escape_html(time)

    local message = ([[
<b>%s</b>
<blockquote expandable>%s</blockquote>

<blockquote><b>%s</b>
<b><i>%s</i></b>
<tg-time unix="%d" format="wDT">%s</tg-time>
</blockquote>
]]):format(sender, content, safe_id, safe_prefix, data.timestamp, safe_time)

    return utils.toJson({
        text = message,
        chat_id = -1000000000, -- FILL This
        parse_mode = "HTML",
    })
end
```
